---
name: LogisVert PDF text extraction requires OCR
description: LogisVert (Quebec energy subsidy) generated PDFs use custom/embedded font encoding that pdftotext cannot decode into readable text; regex parsing of pdftotext output fails silently (garbled output). Use OCR instead.
---

LogisVert "Demande d'aide financière" PDFs (subsidy calculation summaries) are generated by a web app that embeds a custom font encoding. `pdftotext` (poppler) extracts garbled/unusable text from them, even with `-layout`. Regex-based amount parsing against pdftotext output will silently fail (return null) on these files even though the PDF looks normal visually.

**Why:** Found by rasterizing the PDF with `pdftoppm` and visually inspecting the image — text was legible in the render but not in `pdftotext` output, confirming a font-encoding issue rather than a bad PDF or bad regex.

**How to apply:** For this document type, rasterize page 1 with `pdftoppm -png -r 150` then run `tesseract <img> <out> -l fra --psm 6` (French language pack) to get real text. Budget realistic timeouts — full pdftoppm+tesseract pass took ~35s in this environment, so use timeouts of 45-60s, not 30s.

OCR output has quirks to handle when parsing amounts:
- "00" cents sometimes OCR'd as letters "OO"/"oO" right before "$".
- Digit groups can get spurious spaces inserted mid-number (e.g. "18 480,00" → "1 8480 00"), so naive comma/space-group regexes fail. Robust approach: capture the raw digit/space/punctuation run immediately before "$", strip all whitespace, and if it's pure digits with no decimal marker, treat the last 2 digits as cents and the rest as dollars (this correctly reconstructs "1 8480 00" → 18480.00). If it already has a `,`/`.` decimal marker with 2 digits, use that directly.
- Keyword phrases can be split across OCR line breaks with the amount injected in between (e.g. "Vous pourriez avoir [amount] $\ndroit à :"). Match on a shorter/partial keyword phrase (e.g. "pourriez avoir") rather than the full phrase, and search a multi-line window after the match for the dollar amount.
